# novel-outline · 大纲（第 2 步）

> 把契约 concept.md 展开成可逐章执行的章纲 + 伏笔规划 + 人物卡池。

```
pipeline.py gate outline    # 顺序锁：setup done；文件锁：concept.md 存在。exit 1 就停下
```

## 执行步骤

### 1. 读契约

读 `concept.md`（卖点/核心冲突）+ `worldbuilding.md`（硬规则）。大纲服从契约，冲突时改大纲不改契约。

### 2. 三维盘点（强制硬门禁，不许跳过）

```
python3 {SKILL_DIR}/scripts/characters_pool_generator.py --project {书目录}
```

脚本读 concept/worldbuilding/已有卡，产出 `characters-pool.md`：**势力 × 时代 × 家族**三维矩阵（每行：已识别/应有人物/已有卡/缺卡）。

agent 逐格填决策列：**建详卡**（与主角/详卡有直接关系网）/ **建简卡**（出场 2-3 场、影响 1 个核心事件、见证者）/ **不建卡**（一次性龙套）/ **合并到X**（与其他格子重合）。`advance outline` 校验每个格子决策列非空，缺 = 卡住。

### 3. 建人物卡（双层卡）

先读 `references/writing-methods/character-design-methods.md`（三层标签反差人设/配角功能化/双层卡设计），按需再读 character-basics / character-relations。按盘点结果写入 `characters/{角色名}.md`：

**详卡**（模板 `.novel/templates/character-card.md`）必填（G6 校验非空）：
- 三件套：核心性格（≤3 词各配一个行为示例）/ 动机与目标（长期+当前）/ 底线与恐惧（OOC 试金石）
- 优缺点：优点 ≥2 条（每条带代价）/ 缺点 ≥1 条（带触发器，可带偶发回报）——脚本不校验，建卡自检
- 关系行：`与{角色}：关系类型｜张力 1-5｜秘密（无则写「无」）｜现状一句话`
- 个人故事四件套：出身与来处 / 关键转折 / 未了的执念 / 独处时的样子

**简卡**（模板 `.novel/templates/character-card-simple.md`）必填：基本信息（含一句话功能+标签）/ 与详卡的关系（≥1 条）/ 优缺点速记一行（最突出的优点与代价 + 最危险的缺点与触发器）。

通用纪律：
- 卡只记**静态不变量**；当前伤势/位置/心情归 tracking 快照，不进卡
- 关系行含张力与秘密；张力 ≥4 的关系是正文冲突燃料，draft 时优先使用，本章出场时优先引爆或推进
- 关系网两两对账：A 卡写与 B 的关系，B 卡要有对应
- 对账后「详卡↔详卡」关系全部锁详卡；简卡后续与详卡建立直接关系 → 升级详卡

### 4. 写 outline.md

先让脚本搭骨架（章数按篇幅÷平台每章字数自动算，已存在拒绝覆盖）：

```
python3 {SKILL_DIR}/scripts/scaffold_outline.py --project {书目录}
```

**写章纲前三问**（答不上停下补设定，不硬写）：①这章为什么必须存在，跳过读者损失什么 ②本章的本质变化（起→止）③主角的牛逼体现在哪。

在骨架里填六块：
0. **总纲**（scaffold 生成空框）：一句话主线 + 结构划分 + 关键转折点表 + 结局锚点——主题统一的锚
1. **章纲**：逐章「本章目标/关键事件/章尾钩子/新概念」
2. **结构标记**：起承转合/高潮点/分卷职责（15 beats 三层用法见 save-the-cat-beats.md，不每章硬套）
3. **情绪曲线**：逐章「第N章【低/中/高】：情绪要点」——【】强度会被 pacing.md 直接采用，不标则由关键词启发推断
4. **伏笔规划**：F1、F2… 编号，每条标「埋设章/计划回收章/类型」
5. **概念预算**：第一章新概念 ≤3 个，后续每章 ≤2 个；优先深化不新增

**章纲信号纪律**：章纲是给作者的执行指令，不是读者预告——写「王强深夜来电，语气反常」，不写「这通电话暴露王强是内鬼」；禁止写读者反应、后期反转、伏笔答案。

**大纲级 AI 味自检**：否定排比改正面陈述；单场景转折连接词（然而/但是/却）≤1 次；空泛转场（随后/经过一番周折）必须补出谁做了什么。

**方法论按需加载**（只读当次用的）：章纲节奏→outline-rhythm；情绪→emotional-design；冲突→outline-conflict；剧情爆破→plot-booming；母型→save-the-cat-beats；题材写法→书目录 `题材卡.md`；其余查 INDEX 再读单份。

### 5. 推进

```
pipeline.py advance outline    # G6 校验：章节条目/伏笔规划/概念预算/人物卡字段/盘点决策列
```

outline 完成 → 回到根 SKILL.md 入口跑 status，路由到 novel-draft（只要大纲不写正文到这里即可停止，status 会一直提示 draft pending，属正常）。

## 失败分支

- gate 报「setup 未完成」→ 回 novel-init
- advance 报「大纲不合格」→ 补缺失部分重跑
- advance 报「人物卡缺失/字段未填」→ 按第 3 步补卡重跑
- advance 报「盘点缺决策」→ 第 2 步补决策列重跑

## 铁律

- 不写与契约冲突的大纲；大盘纲冲突时改大纲不改契约
- 伏笔规划「埋哪收哪」必须清晰，细节留 draft 发挥
- 人物卡不写动态处境；龙套不建卡
