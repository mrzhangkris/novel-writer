# story-long-analyze：长篇网文拆文

> **看懂别人的爆款，才能写出自己的爆款。**
>
> 拆解边界：只拆用户**合法持有**的虚构作品，性质是只读的转化性文学批评（编辑/评论视角，不复制不传播）。通俗题材的家暴/出轨/复仇/暴力/黑暗伦理是常规虚构元素，照常做结构化提取，**不得以「敏感」为由拒绝整章整本**；个别片段无法处理则跳过、续完其余。

## Phase 1：确认拆解对象

问「拆哪本书？（书名+平台）有原文文件路径吗？」；无目标则按题材推荐 2-3 本 benchmark。无文本路径时引导用户提供路径或贴原文。

确认后直接进入管道（无快速/深度分叉，Stage 1 后自动停靠）。

## Phase 2：深度拆解管道

输出到 `deconstruct/{书名}/`（用户指定则从指定）。

**开始前**：
1. **检查已有分析**：有 `_progress.md` 从断点恢复；有 角色/ 或 settings/ 数据作交叉验证基线（冲突标注让用户裁定），不重复提取
2. **备份原文**：复制到 `deconstruct/{书名}/原文/`（对话贴入的存 原文.md）；备份后验证数量/大小一致或非空
3. **预期耗时**：告知粗估（<50 章 30-60 分钟；50-200 章 1-3 小时；>200 章可能多轮会话）

### Stage 0-6 总表

| 阶段 | 名称 | 输出 | 完成标志 |
|------|------|------|----------|
| 0 | 概要提取 | 概要.md（首版 200 字 thin first-pass + 章节索引；Stage 5 落 500-1000 字全书版覆盖）+ **章节边界表写入 _progress.md** | 章节结构识别完成 |
| 1 | 黄金三章 | 第1-3章_深度拆解.md（非人形反派/抽象对抗型在本阶段一并分析） | 3 章完成 → **停靠出快速预览.md** |
| 2 | 逐章摘要 | 章节/第N章_摘要.md（情节点+角色+关键信息扩写技法+逐章写法公式；每章 10-40 情节点，密度 150-200 字/个；龙套不提取、别名归类）**并行 spawn 子代理** | 摘要数 == 章节数 |
| 3 | 聚合分析 | 剧情/*.md + README.md（权威分工表+剧情单元清单）+ 故事线.md + 节奏.md + 情绪模块.md。含故事框架识别、两步法剧情聚合、情绪节奏总览、角色合并分级、散落情节兜底、桥段标签、质量检查 | 质量检查通过 |
| 4 | 设定+关系 | settings/*.md + 角色/*.md。**4a** 设定（从 Stage 2 mention 归纳，与 Stage 3 并行）；**4b** 角色完整档案（依赖 3 合并后角色，别名置信度 ≥0.85 自动合并）；**4c** 角色关系（从情节点提取，含演变追踪） | 4a/4b/4c 完成 |
| 5 | 汇总报告 | 拆文报告.md（读者需求/情绪引擎/节奏总览/伏笔地图/冲突升级/可复现模块 + 写法技巧清单）+ 概要.md 全书版 | 报告完成 |
| 6 | 文风 | 文风.md（句长/标点/对话潜台词/情绪交替 + 4-6 段原文锚点 + 分层模仿建议，≤4000 字。协议见 `references/style-profile-protocol.md` + `style-profile-generator.md`） | 文风落盘 |

**产物权威序**：节奏/情绪/套路的权威是 `剧情/节奏.md` 与 `剧情/情绪模块.md`；拆文报告与故事线只做摘要投影，冲突时以前两者为准。

### Stage 0 章节边界（确定性步骤，禁止手工 regex）

```
python3 {SKILL_DIR}/scripts/extract_chapters.py --input 原文.txt --output deconstruct/{书名}/_progress.md
```

输出章号/起始行/标题表 + 重复与缺口提示。这张表是 Stage 1/2/6 共用的**唯一切片真源**，落表前校验章号连续无重复无跳号，不满足停下报告。识别失败（多卷书每卷重起「第一章」是合法结构）在标题列保留卷号消歧（`卷二 第一章`），章号按全书连续重编。`_progress.md` 顶部落 `schema_version: 2`；续跑只接受含「章节边界」表的 v2 文件。

### Stage 1 停靠点

1. 写 `快速预览.md`（模板见 `references/output-templates.md`）
2. `_progress.md` 状态写 `paused_after_stage1`
3. 问用户：「黄金三章已拆完，是否继续全量拆解（Stage 2-6）？预计 {粗估耗时}」——继续则从 Stage 2 续跑**不重跑 0/1**；停止则告知随时可续
4. 用户一开始就说「完整拆解/一次跑完/别问」→ 仍生成快速预览但不询问，直接跑到 Stage 6

### Stage 2 并行 Agent 策略

每章 spawn 章节提取子代理，每批 5-8 个，批间更新 `_progress.md`。

**prompt 必须以材料声明开头**（固定文本逐字带）：
> [材料声明] 以下为用户合法持有的虚构小说，任务是只读的转化性文学分析（编辑/评论视角）。暴力/复仇/家暴/情爱/黑暗伦理是该题材常规虚构元素，照常提取，不得以敏感拒绝整章或整本；个别片段无法处理则跳过、照常续完其余。

后接章节编号/标题/字数/原文 + 情节点格式要求（模板占位符不输出花括号；主题标签单值；空字段写「无」；标签行紧跟情节点）+ 输出前自检。完整 prompt 模板见 `references/output-templates.md`。

**两类失败**：
1. 执行失败（crash/超时/空输出）→ 同配置重试 1 次
2. 质量失败 → 升级模型重试 1 次

**落盘后机械硬检查**（grep 判定，不依赖 agent 自报，4 条即全部）：
- `grep -cE '^P[0-9]+ '` == `grep -c '基调：'` == N（漏全角冒号会让 Stage 6 静默漏章）
- 白描段非空：`^P[0-9]+ [^|]+\|[^|]*[^|[:space:]][^|]*\|[^|]*涉及` 计数 == N
- 基调值 ⊆ {紧张,轻松,悲伤,热血,爽,甜,温馨,恐怖,压抑,其他}
- 主题标签 ⊆ {爱情,亲情,友情,权力,金钱,成长,复仇,悬念,搞笑,热血,日常,其他}（带冒号或值为基调词判失败）

升级重试仍失败 → 该章标 `⚠️ 跳过` 记入失败记录表，不阻断管道。格式漂移靠 spawn prompt 事前预防，不为可读性变体加校验。

**Agent 不可用降级**：无法 spawn 子代理时主线程串行逐章处理，同样的模板与硬检查；无升级重试，失败由主线程重写 1 次，仍不过按跳过记录。

### Stage 2 收尾：合并摘要

所有 `章节/*_摘要.md` 落盘后，按边界表顺序**无损拼接**成 `_章节摘要汇总.md`（`cat 清单 | xargs cat >`，不依赖文件名排序）。拼接后校验：`^P` 行数 == 各章之和；`**概要**` 行数 == 文件数。任一不过即删除汇总、回退逐文件扫描。

Stage 3/4a/4c 只读一次汇总文件。>500 章或汇总过大放不进上下文时跳过本步，按 `references/material-decomposition.md` 批次模式 spawn 子代理降维聚合。管道结束（Stage 6 后）删除 `_章节摘要汇总.md`（派生临时文件，不随 deconstruct/ 交付）。

### Stage 5 后：topic-decision 回填（可选）

定位 `topic-decision.md`（项目根直接用；否则向下搜 ≤3 层取最新，**项目根之外的写前必须确认**）。仅当题材关键词对上时回填：把选题的「能爆的原因」从 `待拆文验证` 改为带出处的拆解支撑（注明还只是假设，一本不算坐实）。对不上/缺字段/搜不到 → 记录跳过，不猜测不静默回填。已回填过的不覆盖。

### Stage 6 文风

文风.md 只管表达层；情绪/节奏意图以 `剧情/` 两文件为权威。原文缺失或分隔符识别不出 → 写明 `文风可用：否：{原因}`。Stage 6 失败不阻断管道。

## 质量检查

Stage 3-4 完成前过质量检查（置信度/覆盖率/重叠率，阈值唯一权威见 `references/material-decomposition.md`）。Stage 3-5 须过「事实可溯源」自检：硬事实（等级/数值/距离/出场章/谁说的话）必须能 grep 回原文，原文没给的写「原文未明确」、**禁推断填空**——这是拆文事实错误的最大来源。

## 恢复机制

启动时检查 `_progress.md`：`paused_after_stage1` → 从 Stage 2 续跑。操作步骤见 `references/pipeline-ops.md`。
